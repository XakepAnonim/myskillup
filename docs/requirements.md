# Требования к проекту "Менеджер задач"

## 1. Паспорт проекта

Название: Менеджер задач (Task Manager).

Цель: предоставить пользователю возможность создавать личные задачи, просматривать их и отмечать выполненными.

Целевая аудитория: пользователи, которым необходим простой инструмент для учёта повседневных задач.

Основной пользователь первой версии является студентом, который ведёт список учебных и личных заданий. Его проблема состоит в том, что записи в разных местах мешают видеть оставшиеся задачи и сохранять отметки выполнения между запусками. Первая версия объединяет этот список на одном компьютере.

Тип приложения: консольное приложение на Python.

Первая версия включает создание задач, просмотр списка, отметку выполнения и сохранение данных между запусками.

Статус: документ описывает проектируемое поведение. Функциональность не реализована.

## 2. Уточнение паспорта

Основанием этих документов является ранее выбранный для проекта учебный пример "Менеджер задач". Тема и принятые в этом проекте правила являются авторскими проектными решениями и ожидают проверки преподавателем; их согласование преподавателем по текущим материалам не подтверждено. Ниже приведены два самостоятельно сформулированных примера уточнения неоднозначных требований. Сопоставление с исходным паспортом урока 1.1 по текущим материалам не подтверждено; это не означает, что паспорта не было. Ранее принятый паспорт этой работой не изменяется.

### Формулировка 1

Исходная: "Пользователь должен удобно создавать задачи".

Уточнённая: "Пользователь может создать задачу с непустым названием. Каждая задача получает уникальный идентификатор и начальный статус 'Не выполнена'".

### Формулировка 2

Исходная: "Приложение должно показывать задачи".

Уточнённая: "Приложение отображает идентификатор, название и статус каждой задачи. Если задач нет, выводится сообщение 'Список задач пуст'".

## 3. Функциональные требования

### FR-01. Создание задачи

Пользователь может создавать задачи с непустым названием. Название из одних пробелов не допускается. Каждая задача получает уникальный идентификатор и начальный статус "Не выполнена".

Перед проверкой и сохранением названия применяется strip(). Одинаковые названия допускаются. ID является положительным целым числом; первый ID равен 1, следующий равен максимальному существующему ID плюс 1. Перестановка задач не изменяет их ID.

### FR-02. Просмотр задач

Пользователь может просматривать список задач. Для каждой задачи отображаются идентификатор, название и статус.

### FR-03. Завершение задачи

Пользователь может отметить существующую задачу как выполненную по её идентификатору. Если идентификатор не найден, отображается ошибка, весь список остаётся неизменным. Повторное завершение уже выполненной задачи сохраняет её статус и не создаёт новую задачу. Текстовый ввод преобразуется в положительный целочисленный ID до вызова логики задач.

### FR-04. Сохранение задач

Задачи сохраняются в локальном файле JSON в кодировке UTF-8. После повторного запуска приложения задачи и их статусы восстанавливаются. Отсутствующий файл при первом запуске означает пустой список.

При загрузке проверяются структура списка и каждой задачи, типы полей, положительность и уникальность ID, непустое после strip() название и допустимый статус. Повреждённый JSON, нарушение схемы или другая ошибка чтения приводят к сообщению об ошибке и завершению запуска без сохранения. Ошибочный файл не заменяется автоматически пустым списком.

Если запись после изменения задач не удалась, пользователь получает предупреждение, что изменение не сохранено. Изменение остаётся в памяти текущего запуска; сообщение об успешном сохранении не выводится. Защита от частичной записи пока отдельно не спроектирована и не заявляется.

### Ограничения и проверяемое свойство качества

C-01. Первая версия работает локально на Python с консольным интерфейсом, без регистрации и сетевых сервисов.

C-02. Постоянное хранение ограничено одним локальным JSON-файлом в UTF-8; база данных и синхронизация не входят в первую версию.

NFR-01. При вводе неизвестной команды "wrong" или нечислового ID "abc" в описанных ручных проверках приложение показывает понятное сообщение и возвращается к меню без необработанного traceback. Список задач не изменяется. Проверка этого свойства запланирована в AC-12 и TC-14, её выполнение пока не заявляется.

## 4. Пользовательские сценарии

### SC-01. Создание задачи

Предусловие: приложение запущено.

Ход:
1. Пользователь выбирает создание задачи.
2. Вводит название "Подготовить отчёт".
3. Подтверждает создание.

Ожидаемый результат: задача создана с уникальным идентификатором и статусом "Не выполнена".

Альтернативный ход: если на шаге 2 введены только пробелы, выполняется SC-02. Показано сообщение об ошибке, список и количество задач не меняются.

Связанные требования: FR-01.

### SC-02. Создание задачи без названия

Предусловие: приложение запущено.

Ход:
1. Пользователь выбирает создание задачи.
2. Вводит строку из пробелов.
3. Подтверждает создание.

Ожидаемый результат: задача не создаётся, отображается сообщение об ошибке, исходный список и количество задач не меняются. Этот сценарий является ошибочной веткой SC-01.

Связанные требования: FR-01.

### SC-03. Завершение задачи

Предусловие: существует невыполненная задача.

Ход:
1. Пользователь открывает список задач.
2. Выбирает идентификатор существующей задачи.
3. Отмечает задачу выполненной.

Ожидаемый результат: статус выбранной задачи изменяется на "Выполнена", остальные задачи не меняются.

Альтернативный ход: введён неизвестный ID, показано сообщение об ошибке, весь список неизменен. Если задача уже выполнена, её статус остаётся прежним и дубликат не создаётся.

Связанные требования: FR-02, FR-03.

### SC-04. Восстановление данных

Предусловие: существует сохранённая задача.

Ход:
1. Пользователь завершает приложение.
2. Повторно запускает программу.
3. Открывает список задач.

Ожидаемый результат: сохранённая задача отображается с прежним статусом.

Альтернативный ход: отсутствующий файл означает первый запуск с пустым списком. Повреждённый файл или нарушение схемы приводят к сообщению об ошибке и завершению запуска без сохранения и без автоматической перезаписи файла.

Связанные требования: FR-04.

## 5. Критерии приёмки

AC-01 (FR-01): при вводе названия "Подготовить отчёт" создаётся задача с указанным названием; ввод " Подготовить отчёт " даёт название "Подготовить отчёт" после strip().

AC-02 (FR-01): каждая новая задача получает положительный целочисленный ID, отличный от существующих. В пустом списке ID равен 1, иначе максимальному существующему ID плюс 1. Одинаковые названия допускаются; перестановка списка не изменяет ID задач.

AC-03 (FR-01): после создания задача имеет статус "Не выполнена".

AC-04 (FR-01): при пустом названии или названии из пробелов задача не создаётся, отображается сообщение об ошибке, список и количество задач остаются неизменными.

AC-05 (FR-02): список отображает идентификатор, название и статус каждой задачи. Если задач нет, выводится сообщение "Список задач пуст".

AC-06 (FR-03): существующая задача переводится в статус "Выполнена", другие задачи не изменяются. При неизвестном идентификаторе отображается ошибка, весь список остаётся неизменным.

AC-07 (FR-04): после повторного запуска сохранённые задачи и их статусы доступны пользователю.

AC-08 (FR-04): при первом запуске без файла данных приложение запускается без ошибки и показывает пустой список задач.

AC-09 (FR-04): если JSON повреждён, структура неверна, ID повторяются или неположительны, название пусто либо статус неизвестен, загрузка отклоняется. Пользователь видит сообщение об ошибке; запуск завершается без сохранения, исходный файл не перезаписывается автоматически.

AC-10 (FR-04): если запись в файл после успешного изменения задач невозможна, показано предупреждение "Изменение не сохранено". Изменение остаётся только в памяти текущего запуска, сообщение об успешном сохранении отсутствует.

AC-11 (FR-03): повторное завершение выполненной задачи сохраняет её статус "Выполнена", число задач и остальные задачи не меняются.

AC-12 (NFR-01): для неизвестной команды "wrong" и нечислового ID "abc" по отдельности показано понятное сообщение, затем меню. Необработанного traceback нет, список задач неизменен.

## 6. Ошибочный критерий

Ошибочная формулировка: "Приложение должно работать быстро и удобно".

Причина: формулировка субъективная и не содержит проверяемого результата.

Исправленная формулировка: "При запросе списка из 100 задач приложение отображает идентификатор, название и статус каждой задачи без пропусков".

Этот пример используется для демонстрации правильной формулировки критерия, но не входит в обязательные AC первой версии.

## 7. За пределами первой версии

В первую версию не входят:
- Редактирование задач.
- Удаление задач.
- Поиск и фильтрация.
- Авторизация.
- Синхронизация между устройствами.
- Графический интерфейс.

Эти функции не входят в обязательную приёмку первой версии. Принятое в этом проекте распределение объёма приведено ниже.

| Сейчас | Позже | Не планируется в учебном проекте |
|---|---|---|
| Создание, просмотр, завершение задач, сохранение и загрузка JSON | Редактирование, удаление, поиск и фильтрация, графический интерфейс | Авторизация, синхронизация между устройствами |

Хранение только в памяти допускается как промежуточный этап реализации, но не заменяет JSON в целевой первой версии.

## 8. Открытые вопросы

Для этих документов используются ранее выбранный для проекта учебный пример, консольный интерфейс, локальный JSON в UTF-8 и принятые в этом проекте правила FR-01–FR-04. Статусы "Не выполнена" и "Выполнена" сохранены одинаковыми в требованиях и архитектуре.

Сопоставление с ранее принятым паспортом урока 1.1 остаётся непроверенным по текущим материалам. Этот вопрос не является основанием для изменения самого паспорта.

Механизм защиты от частичной записи является отдельным отложенным проектным решением; гарантия атомарного сохранения пока не заявляется.
