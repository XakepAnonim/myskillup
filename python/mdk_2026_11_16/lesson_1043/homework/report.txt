МДК 01.02. Домашняя работа по теме 3.1

Три сбоя воспроизведены в учебных программах этого курса. Проверялись
специально сохранённые ошибочные версии функций. Реальные результаты
вызовов записаны в defects-actual.json. Серьёзность и приоритет ниже
являются предложенной оценкой влияния на работу этих программ.

1. Нормализация телефона оставляет скобки в результате.
Действие: вызвать normalize_phone_old("8 (912) 345-67-89").
Ожидалось: "+79123456789" по примеру в документации.
Фактически получено: "+7(912)3456789".
Дефект: из исходной строки удаляются пробелы и дефисы, но не скобки.
Серьёзность major. Предлагаемый приоритет P2, поскольку обычная форма
записи телефона нарушает контракт основной функции нормализации.
Новая normalize_phone проходит этот случай и проверки ошибочных номеров.
Исходная версия и исправление находятся в решении шага 3999.

2. Выбор нуля лучших результатов возвращает весь список.
Действие: вызвать top_n_buggy([70, 95, 80], 0).
Ожидалось: пустой список [].
Фактически получено: [95, 80, 70].
Дефект: ветка "if n else scores" при n == 0 возвращает scores.
Серьёзность major. Предлагаемый приоритет P2, поскольку результат запроса
нарушает заданное ограничение числа элементов.
Исходная версия и исправление находятся в решении шага 4008.

3. Второй максимум ошибочно совпадает с первым при повторах.
Действие: вызвать second_max_buggy([9, 9, 5]).
Ожидалось: 5, второе по величине различное число.
Фактически получено: 9.
Дефект: берётся предпоследний элемент отсортированного списка без
исключения повторяющихся максимальных чисел.
Серьёзность major. Предлагаемый приоритет P2, поскольку программа выдаёт
неверный результат на допустимых данных.
Исходная версия и исправление находятся в прежней работе шага 3605,
каталог python/mdk_2026_11_07/lesson_761/step_3605 существующего проекта.

Проверки программы истории дефекта

Позитивная проверка
Ввод по строкам: 5, new, assigned, fixed, verified, closed.
Ожидаемый вывод: История корректна: Закрыт, переоткрытий: 0
Фактический вывод совпал. Проверяется штатное завершение жизненного цикла.

Негативная проверка
Ввод по строкам: 4, new, assigned, fixed, closed.
Ожидаемый вывод: Ошибка: в шаге 4 переход fixed -> closed запрещён
Фактический вывод совпал. Проверяется отказ закрывать дефект без проверки.

Дымовая проверка
Ввод по строкам: 1, new.
Ожидаемый вывод: История корректна: Новый, переоткрытий: 0
Фактический вывод совпал. Проверяются запуск и минимальная корректная история.

Регрессионная проверка
Ввод по строкам: 11, new, assigned, fixed, reopened, assigned, fixed,
reopened, assigned, fixed, verified, closed.
Ожидаемый вывод: История корректна: Закрыт, переоткрытий: 2
Фактический вывод совпал. Этот случай оставлен для следующих изменений,
чтобы сохранить подсчёт нескольких переоткрытий.

Все четыре проверки программы выполнены отдельными запусками Python.
В checks.json сохранены stdin, ожидаемые строки, фактические stdout,
stderr и коды завершения. У всех четырёх запусков код завершения 0,
stderr пустой, stdout точно совпал с ожиданием.
